# Контроль кассовой дисциплины по видео — Datathon 26 (ForteBank)

AI-сервис анализирует видеозапись работы кассира (.mov), находит визуально наблюдаемые признаки
возможных нарушений и показывает проверяющему **тип, таймкод, 1–3 кадра-доказательства, описание
и норму** (документ, пункт, дословная цитата). Все модели работают **локально**, без облачных AI-сервисов.

> Результат — подсказка для проверки человеком, а не юридическое или дисциплинарное заключение.
> Сервис не делает выводов о том, чего не видно на видео (суммы, проводки, сверки).

---

## 1. Как пользоваться

**Веб-интерфейс:** открыть адрес сервиса → перетащить видео → «Проверить видео». После обработки
появятся вердикт («Нарушение не обнаружено» / «Обнаружены признаки возможных нарушений»), карточки
нарушений с кадрами; клик по таймкоду перематывает видео.

**API** (раздел 10 ТЗ), ключ в заголовке `X-API-Key`:

```bash
curl -X POST https://<адрес>/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
# -> {"job_id": "3f2a9c1e04ab", "status": "processing"}
curl https://<адрес>/api/v1/jobs/3f2a9c1e04ab -H "X-API-Key: <ключ>"
# -> {"job_id": "...", "status": "done", "verdict": "violation", "violations": [...]}
```

Ответ строго по схеме ТЗ: `verdict` (`violation` / `no_violation`), `violations[]` с полями
`type`, `timecode_sec`, `description`, `evidence_frames[]` (1–3 JPEG в base64). Запросы без верного
ключа отклоняются (401). Ответ гарантированно приходит за < 5 минут с момента загрузки,
включая ожидание в очереди.

## 2. Установка и запуск (macOS, Apple Silicon)

```bash
brew install python@3.11 ffmpeg
python3.11 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt mlx-vlm
# скачать веса VLM один раз (~5.6 ГБ); дальше интернет для анализа не нужен
python -c "from mlx_vlm import load; load('mlx-community/Qwen2.5-VL-7B-Instruct-4bit')"
```

Запуск локально: `VLM_BACKEND=mlx API_KEY=<ключ> ./run.sh` → http://localhost:8000
Боевой запуск с публичным адресом: `./start_jury.sh` (ключ в `.api_key`, домен ngrok в `.ngrok_domain`).
Веса детектора YOLOX-s (36 МБ) скачиваются автоматически при первом запуске.

Проверки:
```bash
python -m scripts.jury_check --url http://localhost:8000 --key <ключ> --video путь/к/видео.mov  # как у жюри
VLM_BACKEND=mlx python -m scripts.evaluate --videos <папка с .mov> --labels <разметка.csv>  # качество
```

## 3. Архитектура

```
видео .mov
  └─ 1. кадры (OpenCV, 3 кадр/с)
  └─ 2. детектор YOLOX-s (onnxruntime): люди, ноутбук, предметы
  └─ 3. рабочая зона кассира (ноутбук + стол + сейф) и место кассира (по сидящей позе)
  └─ 4. моменты-кандидаты:
        • кассир встала и ушла с места  • в комнату вошёл человек  • кассир на месте (каждые 2–6 с)
  └─ 5. локальная VLM Qwen2.5-VL-7B (4 бит, MLX) отвечает на ТОЧЕЧНЫЕ вопросы по УВЕЛИЧЕННЫМ фрагментам:
        • после ухода: «перечисли предметы на столе», «экран ноутбука заблокирован?», «сейф открыт?»
        • кассир на месте: «телефон в руках?», «пьёт/ест?», «личная сумка на столе?» (с подтверждением на соседних кадрах)
        • вход: «посторонний за спиной кассира?», «два посетителя сразу?», «инкассатор показал документ?»
  └─ 6. реестр правил app/rules.json: тип → документ, пункт, дословная цитата
  └─ 7. JSON по схеме ТЗ + карточки в интерфейсе
```

**Почему так.** 42 обучающих ролика без типов нарушений — слишком мало, чтобы обучать модель на видео:
она запомнила бы ракурс. Готовый детектор + точечные вопросы к VLM переносятся на новые ракурсы.
Мы проверили: VLM плохо выбирает из длинного списка нарушений, но надёжно отвечает «да/нет» по
крупному фрагменту кадра. **Ссылку на норму модель не генерирует** — она берётся только из реестра.

**Модели (все с лицензией, разрешающей коммерческое использование):**

| Компонент | Модель | Лицензия |
|---|---|---|
| Детектор людей и предметов | YOLOX-s (Megvii), ONNX | Apache 2.0 |
| Мультимодальная модель | Qwen2.5-VL-7B-Instruct, 4 бит (mlx-community) | Apache 2.0 |
| Инференс | onnxruntime, MLX / mlx-vlm | MIT |
| Сервис | FastAPI, OpenCV | MIT / Apache 2.0 |

Ultralytics YOLO сознательно не используется (AGPL).

## 4. Нормативные источники и сопоставление с видео

Тексты сверены с adilet.zan.kz 17.10.2026 (действующие редакции, включая изменения от 10.11.2025 и 16.03.2026).

1. [Правила осуществления кассовых операций и операций по инкассации банкнот, монет и ценностей в банках второго уровня…, утв. постановлением Правления НБРК от 29.11.2019 № 231](https://adilet.zan.kz/rus/docs/V1900019680)
2. [Правила организации охраны и устройства помещений банков второго уровня…, утв. постановлением Правления НБРК от 24.02.2020 № 14](https://adilet.zan.kz/rus/docs/V2000020075)

Принцип: каждому типу нарушения в `app/rules.json` сопоставлены документ, пункт и дословная цитата.
Сервис показывает норму, только если пункт сверен вручную (`verified: true`). Где прямой нормы НБРК
нет, так и пишется: «внутренние требования банка».

## 5. Распознаваемые типы нарушений

| Тип | Что видно на видео | Норма |
|---|---|---|
| Наличные или ценности оставлены без присмотра | кассир уходит, на столе остаются купюры, документы, сумка, планшет | № 231, п. 20 (ч. 2), п. 22 |
| Компьютер не заблокирован при уходе | кассир уходит, на экране открыта программа | внутренние требования банка (ИБ) |
| Сейф оставлен открытым | кассир отходит, дверца сейфа открыта | № 231, п. 20 (ч. 2), п. 80 |
| Посторонний в кассовой зоне | человек заходит за стол на сторону кассира | № 14, п. 16 подп. 1, 5 |
| Второй посетитель во время операции | к столу подходит второй человек, пока обслуживается первый | № 231, п. 20 (ч. 2), п. 22 |
| Приём ценностей у инкассатора без проверки | сумка передана, передача/проверка документа не видна | № 231, п. 24 |
| Личные вещи / телефон на рабочем месте | телефон в руках кассира, сумка или одежда на столе | № 231, п. 12 |
| Приём пищи/напитков на рабочем месте | кассир пьёт или ест у стола с наличными | внутренние требования банка |
| Пересчёт не в присутствии клиента | клиент уходит до окончания пересчёта | № 231, п. 20 (ч. 1), п. 31 подп. 4 |
| Подозрительные действия с наличными | купюры уходят к одежде/под стол | № 231, п. 14, п. 31 подп. 4 |

Таймкод: для «ушёл и оставил» — середина между моментом, когда кассир встал, и уходом из комнаты;
для остальных — момент, когда событие впервые видно. Нарушения «по бездействию» (не проверил документ)
привязаны к моменту, когда действие должно было произойти.

## 6. Качество на обучающем наборе (42 ролика, 22 с нарушением)

| Метрика | Значение |
|---|---|
| Верный вердикт по видео | 71% (30 из 42) |
| Ложные тревоги | 3 из 20 нормальных роликов |
| Пропуски | 9 из 22 роликов с нарушением |
| Ошибка таймкода (медиана) | 3,3 с |
| Время обработки | 25–230 с на ролик (M1 Pro, 16 ГБ) |

Подбор шёл итерациями (8 версий за ночь), сравнение версий — `scripts/evaluate.py`.

## 7. Ограничения и известные ошибки

- **Пропускаем:** незакрытую дверь кассы; телефон, который виден меньше 3 секунд; второго клиента,
  когда он быстро садится; постороннего при ракурсе «кассир лицом к камере»; тонкие манипуляции
  с купюрами при пересчёте.
- **Ложные тревоги:** бумаги на столе после ухода кассира в конце дня; приход инкассатора, если
  передача документа не видна в кадре; клиент, вставший у стола, иногда принимается за постороннего.
- Зона кассира определяется по ноутбуку; если ноутбука нет в кадре — по позиции кассира
  в начале видео (менее точно).
- Очередь: видео обрабатываются по одному. При 5+ одновременных загрузках последние анализируются
  в сокращённом режиме, чтобы уложиться в 5 минут.

## 8. Как развивать

Дообучение по разметке проверяющих (их «согласен/не согласен» по каждой карточке), новые типы — через
реестр правил и новые точечные вопросы без изменения архитектуры, пакетная обработка архива камер,
перенос в контур банка на сервер с GPU (модели и веса уже локальные).

## Структура

```
app/main.py              сайт и API
app/jobs.py              очередь задач, бюджет времени от загрузки
app/pipeline/v2.py       основной анализ: детектор + зоны + точечные вопросы к VLM
app/pipeline/vlm.py      локальная VLM (MLX)
app/pipeline/yolox_onnx.py  детектор YOLOX
app/rules.json           реестр норм (единственный источник ссылок)
scripts/evaluate.py      оценка качества, scripts/jury_check.py — проверка как у жюри
start_jury.sh            боевой запуск с публичным адресом
```

Видео датасета в репозиторий не входят (по правилам хакатона используются только в его рамках).
